# 一起听 小程序技术验证（微信优先，QQ 也能跑）

先确认小程序在锁屏或切到后台时能做到下面三件事，再决定要不要把一起听做成小程序：

| 测试 | 要回答的问题 | 怎样算通过 |
|---|---|---|
| 一 A | 一首放完，在 `onEnded` 里直接换 `src`，后台能不能接着放下一首 | 锁屏后连续听到第 1、2、3 首（第 n 首每 3 秒响 n 声高音） |
| 一 B | 后台能不能联网：放完先发 HTTP 请求再换歌 | 同上；失败说明后台不能联网，只能提前取地址 |
| 二 | 后台时 WebSocket 还通不通，服务端发来的暂停 / 播放 / 拖进度 / 换歌能不能执行 | 服务端日志里每条指令都有手机的回报，且状态对得上 |

微信文档写明：小程序切到后台 5 秒后 JS 会被「挂起」，但**用了后台音乐播放时不会挂起，可以在后台持续运行**
（[运行机制](https://developers.weixin.qq.com/miniprogram/dev/framework/runtime/operating-mechanism.html)）。
这几项测试就是在真机上确认这一点。

代码用微信的写法（`wx.*`、`.wxml`、`.wxss`），QQ 小程序兼容这种写法，同一个目录可以直接用 QQ 开发者工具打开。
`utils/probe.js` 里会自动选 `wx` 或 `qq`。

这里的代码只用于测试，不接入 bot，也不改动一起听本身。测完可以整个目录删掉。

## 文件

- `server.py`：测试服务端。提供测试音频（本地生成，不涉及版权）、WebSocket（每 5 秒发一次 tick，测试二按脚本发指令），并把手机发回来的日志打印出来，同时写进 `probe-log.jsonl`。
- `miniapp/`：小程序本体，只有一个页面。

## 准备

1. 在 [微信公众平台](https://mp.weixin.qq.com) 注册小程序，主体选「个人」，记下 AppID（「开发管理 → 开发设置」）。
2. 在 `miniapp/project.config.json` 里把 `appid` 改成你的 AppID。
3. 服务端需要一个 https 地址。最简单是在现有的 Cloudflare 隧道里加一个子域名，比如 `listen-probe.isekai-inn.uno`，指向 `http://localhost:8091`。cloudflared 现在借用的是 nonebot 容器的网络，所以 server.py 要在 nonebot 容器里运行（见下一节）。
4. 在 `miniapp/config.js` 里把 `HOST` 改成这个域名（不带 `https://`）。

## 运行服务端

在服务器上，用 nonebot 容器里现成的 Python 和依赖：

```bash
docker cp ~/myTest/miniapp_probe/server.py mytest-nonebot:/tmp/probe_server.py
docker exec -it mytest-nonebot python /tmp/probe_server.py --port 8091
```

或者在任何装了 `fastapi` 和 `uvicorn` 的机器上：`python server.py --port 8091`。

浏览器打开 `https://<你的域名>/audio/2.wav` 能听到声音，就说明服务端和隧道都通了。

## 装到手机上

1. 用 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html) 导入 `miniapp/` 目录，填上 AppID。
2. 测试域名没有备案，也没有在后台配成合法域名，所以：
   - 开发者工具「详情 → 本地设置」里勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」（`project.config.json` 里已经设了 `urlCheck: false`）；
   - 点「预览」，用手机微信扫码打开；打开后点右上角「…」→「开发调试」→「打开调试」，小程序会重启。不开调试模式时，请求会被域名校验拦下。
3. 背景音频的后台播放（`requiredBackgroundModes: ["audio"]`）在开发版和体验版上直接生效，不用提交审核。

想顺便测 QQ：在 `project.config.json` 填上 `qqappid`，用 QQ 小程序开发者工具打开同一个目录，步骤相同。

## 测试步骤

每个测试都从头开始：点按钮后立刻锁屏，**期间不要解锁**，等测完再解锁看结果。服务端终端会实时打印手机发来的日志，括号里的「晚到 xx ms」很大，说明那条消息是在手机上积压了一阵才发出来的（后台时被冻住了）。

1. **测试一 A**：点按钮后锁屏，听 1 分钟左右。能依次听到 1 声、2 声、3 声、4 声高音就是通过。
2. **测试一 B**：同上。如果第 1 首放完就停了，看日志里 `/next 请求失败` 的原因。
3. **测试二**：点按钮后 15 秒内锁屏，然后等大约 90 秒：
   - 第 25 秒：暂停（应该没声音）
   - 第 35 秒：继续播放
   - 第 45 秒：拖到第 5 秒
   - 第 60 秒：换成第 2 首（120 秒长）
   - 第 80 秒：暂停
   服务端日志里每条「发出指令」后面都应该跟着一条「指令 #n 执行后」的回报。

iPhone 和安卓最好各测一遍；同一台手机也可以分别试锁屏和切到别的 App 两种情况。

## 测完把这些发给我

- 服务端终端的输出，或者 `probe-log.jsonl`；
- 每个测试实际听到了什么；
- 手机型号、系统版本、微信（或 QQ）版本。

我会根据结果判断小程序能不能解决后台连续播放和同步，再决定下一步。

## 验证结果（2026-10-30，安卓，微信开发版 + 调试模式）

三项都通过：只要**切到后台时音乐已经在放**，小程序在后台就一直运行，能换歌、能联网、WebSocket 不断。

| 测试 | 结果 |
|---|---|
| 一 A：放完直接换 `src` | 后台连续放了 6 首，每次换歌约 2 秒没声音（新音频缓冲） |
| 一 B：放完先发 HTTP 再换 | 后台连续放了 6 首，请求 0.5–1.4 秒，加缓冲共 2.3–3.4 秒没声音 |
| 二：WebSocket 远程控制 | 后台 80 秒里 WebSocket 一直连着，tick 每 5 秒准时到；暂停、继续、拖进度、换歌、暂停 5 条指令都在 0.1 秒内执行 |

要注意的：

- **切后台那一刻音乐必须在放。** 第一次测试二点完按钮 1.5 秒就锁屏，音乐还在缓冲，结果 5 秒后小程序被挂起、WebSocket 断开，之后 2 分钟没有任何回调（但声音一直在放）。等 `onPlay` 之后再锁屏就正常了。
- **后台音乐一停，JS 会被限速然后挂起。** 一首放完没接上时，心跳间隔从 10 秒变成 15、22、51 秒。所以下一首要提前取好地址，在 `onEnded` 里马上换。
- **播放器状态读数不可靠。** 一首放完后 `currentTime`、`paused` 不会更新，要以事件（`onEnded`、`onTimeUpdate`、`onPause`）为准。
- **新地址开始播放前有约 2 秒缓冲**，拖进度（`seek`）几乎是立刻的。
- 手机到 Cloudflare 的 WebSocket 握手偶尔会超时或卡住，要有超时重连。正式部署走国内备案域名后应该会好很多。

还没测：iPhone、QQ 小程序、不开调试模式的体验版。

## 如果技术验证通过：上线前要知道的

- **只能用体验版给群友用。** 个人主体的小程序最多 15 个体验成员（[微信文档](https://developers.weixin.qq.com/miniprogram/introduction)）。正式发布要先完成小程序备案；「音乐」属于前置审批类目，需要《网络文化经营许可证》，个人主体拿不到。
- **服务器域名要 ICP 备案。** 体验版不开调试模式时也会校验合法域名；现在的 Cloudflare 隧道域名不能备案。这一点在体验版上具体怎么限制，要在后台实际确认。
- **登录要换成微信身份。** 小程序只能拿到 openid，拿不到 QQ 号，需要用验证码把 openid 和 QQ 号绑定（群里发 `/一起听 登录 123456` 那一套可以复用）。
